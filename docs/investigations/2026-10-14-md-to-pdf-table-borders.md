# Markdown表罫線のPDF出力調査

- 日付: 2026-10-14
- 報告: Markdownファイルを表示すると表の罫線は見えるが、PDF化すると罫線が再現されない。
- 目的: Markdown表示経路とPDF生成経路を確認し、罫線が失われる原因と影響範囲を特定する。
- 計画: 関連画面・スタイル・PDF出力処理を追跡し、CSS適用や出力方式を比較する。
- 実装: 調査後、必要な修正内容があればここに記録する。
- 評価: 調査で確認したファイル・根拠・再現/検証結果をここに記録する。

## 調査結果

- Markdown表は `src/ui/js/app.js` でHTMLの `<table>`, `<th>`, `<td>` に変換される。
- 画面表示では `src/ui/css/style.css` の通常ルール（293–295行目）が `border: 1px solid var(--border-color)` を指定する。
- `:root`（22–24行目）の `--border-color` は `rgba(255, 255, 255, 0.08)`。暗色のMarkdownカード上では白い薄線として見える。
- PDF出力は `src/app/main_gui.cpp` の `export_markdown_to_pdf()` からWebView2 `PrintToPdf` を呼ぶ（1416行目以降）。印刷CSSは表本文とワークスペースを白背景にするが（428行目以降）、`th`/`td` の文字色だけを黒へ変更し、表罫線の色は上書きしない（452–461行目）。
- そのためPDFの白背景上でも罫線が `rgba(255,255,255,0.08)` のまま描画され、白にほぼ溶け込む。罫線スタイル自体が削除されているのではなく、通常テーマ用の低コントラスト色が印刷時に残るのが直接原因と判断できる。
- 印刷時の `ShouldPrintBackgrounds=TRUE`（`main_gui.cpp` 1497行目）は背景印刷設定であり、CSSの罫線色を印刷向けに変える指定ではない。

## 評価・対応

- ソース上で通常表示とPDF出力のスタイル差を追跡し、報告された症状と一致する原因を特定した。
- この依頼は調査であり、コード修正と実機PDF再生成は未実施。実機での再現は未確認。
- 修正する場合は `@media print` 内で `.markdown-content th, .markdown-content td` の `border-color` を濃いグレー（例: `#999`）へ明示するのが最小の対応。
- Graphifyは起動コマンドが参照するPython 3.13実行ファイルが見つからず、コードベース解析には使用できなかった。直接ソースを調査した。
