# 計画書: バージョンを v5.0.0 にする (v1.0)

## 経緯
ユーザー指示「v5.0.0にして」(Markdown 内 HTML 対応の作業中に受領)。指示の内容そのものがこの計画の範囲であり、それ以外は変更しない。

## 目的
現行の v4.3.0 から v5.0.0 へ、バージョン表記と変更履歴を更新する。v4.3.0 (2026-10-27) 以降に入った変更 (セキュリティ修正、不具合修正 2 件、同梱ライブラリ更新、Markdown 内 HTML 対応) を、変更履歴に事実のとおり書く。

## 現状分析
- 命名規則 (`HISTORY.md` / `HISTORY_jp.md`): 1 桁目 = 機能追加、2 桁目 = バグ修正、3 桁目 = その他。今回は新機能 (Markdown 内 HTML) を含むので、1 桁目を上げる v5.0.0 は規則に合う。
- 前回のバージョン更新 (commit `c175e74`) が触ったファイル、および現在 `4.3.0` が書かれている箇所 (実際に検索して確認):
  - `src/app/QuickMarkPDF.rc`: `FILEVERSION 4,3,0,0`、`PRODUCTVERSION 4,3,0,0`、`FileVersion "4.3.0.0"`、`ProductVersion "4.3.0.0"`
  - `src/ui/index.html:204`: `Ver. 4.3.0` (アバウト画面)
  - `README.md` / `README_jp.md`: 「現在のバージョン」、リリースページへのリンク 2 件 (タグ `v4.3.0`)
  - `docs/about.md` / `docs/about_jp.md`: `Ver. v4.3.0`
  - `docs/spec.md` / `docs/spec_jp.md`: バージョン行
  - `docs/distribution/readme.txt` / `readme_jp.txt`: 配布パッケージのバージョン
  - `HISTORY.md` / `HISTORY_jp.md` / `docs/distribution/history.txt` / `history_jp.txt`: 変更履歴 (先頭に v5.0.0 を追加)
- `src/app/*.manifest` の `assemblyIdentity version="1.2.1.0"` は、製品バージョンとは無関係の古い値で、前回の更新でも触っていない。今回も変更しない。
- 現在のバージョン表記と、実際にビルドする exe の版情報 (`.rc` から生成) は、同じ値にそろえる必要がある。

## 変更内容
1. 上記のバージョン表記をすべて v5.0.0 (rc は `5,0,0,0` / `"5.0.0.0"`、アバウト画面は `Ver. 5.0.0`) に更新する。
2. 変更履歴 4 ファイルの先頭に `v5.0.0 — 2026-11-23` を追加する。内容は結果文書 (`plans/2026-11-23_脆弱性修正_結果_v1.0.md`、`…暗号化PDF描画と上書き後キャッシュ修正_結果_v1.0.md`、`…同梱ライブラリ更新_結果_v1.0.md`、`…Markdown内HTML許可_結果_v1.0.md`) に書いた事実だけを使う。
3. README のリリースリンクは、前回の慣例どおり v5.0.0 のタグを指すようにする。**タグ `v5.0.0` を打ってリリースが公開されるまで、この 2 つのリンクは存在しないページを指す**。
4. 変更しないもの: ソースコードの動作、`dist` 以外のビルド成果物、manifest、過去バージョンの記述、`docs/investigations/` と `plans/` の過去文書。
5. コミット・タグ・プッシュはしない (別途ユーザーの指示を待つ)。

## 検証方法
- `4.3.0` / `4,3,0` の残りを、`HISTORY*` の過去記述と過去の計画書・調査文書を除いて検索し、0 件であること。
- `python scripts/build.py all` で本番ビルドを作り、`dist/QuickMarkPDF.exe` の FileVersion / ProductVersion が `5.0.0.0` であること。
- ビルドしたバイナリで、テスト用の文字列が含まれていないこと、ASLR / DEP / HighEntropyVA が有効なこと、`dist` の DLL のハッシュが検証済みアーカイブと一致すること、`python scripts/check_dependency_updates.py --verify-vendor` が成功すること。
- 起動中の `QuickMarkPDF.exe` があれば、`dist` を上書きできないため、ユーザーに終了をお願いする (こちらからは終了させない)。

## リスク
- バージョンの書き換え漏れ (README と exe の版が食い違う)。検索で残りを確認して抑える。
- リリース前にリンクが切れる (上記 3)。
- `dist` の exe が起動中だとビルド成果物を更新できない。その場合は、ビルド自体はビルド用フォルダに作り、`dist` 反映をユーザーの終了後に行う。
