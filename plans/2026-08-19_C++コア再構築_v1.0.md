# C++コア再構築 計画書 v1.0

作成日: 2026-08-19
対応する完了条件: 「C++側の自動テストが全passすれば完了」(ユーザー指定)

## 1. 目的・背景

[`plans/2026-08-19_Python版自動テスト整備_v1.0.md`](2026-08-19_Python版自動テスト整備_v1.0.md)で整備した自動テストプログラム完成を受け、C++実装を再開する。[`CPP_PORT_POSTMORTEM.md`](../CPP_PORT_POSTMORTEM.md)により、C++実装は一度すべて破棄されているが、git履歴（`f968e19`の親コミット）には放棄前の到達点が残っている。

## 2. 現状

- `core/native/engine.h/.cpp`（`WorkingDocument`: ページ参照・回転・並べ替え・削除・undo）と `pdf_backend.h/.cpp`（PDFiumを実行時ロードし、inspect/save/render_page/render_page_at_dpiを提供）は、破棄前の時点で20件のCTest相当テストとともに実装済みだった。コミットメッセージから、実PDF・欠損ファイル・非PDFファイルに対して動作確認済みであることが確認できる。
- ただし `WorkingDocument` は低レベルのページ参照モデルのみで、Python版 `PDFManager` が持つ複数ファイルのオーケストレーション（重複排除・パスワード追跡・上書き保存・名前を付けて保存・画像エクスポート・単一ファイルクローズ）に相当する層が無かった。
- 画像出力用のエンコーダ（PNG/JPEG書き出し）も未実装だった。
- `third_party/pdfium/`（PDFiumバイナリ）は`.gitignore`対象で、破棄時に失われていた。

## 3. 変更方針

1. git履歴から破棄前の `engine.h/.cpp`、`pdf_backend.h/.cpp`、`engine_tests.cpp`、`main_cli.cpp`、`build_native.py`、`bundle_html.py`、`scripts/fetch_pdfium.ps1` を復元する（UIレイヤーは復元しない — 失敗したのはUI/検証プロセスであり、このバックエンド部分ではないため）。
2. `scripts/fetch_pdfium.ps1` でPDFiumバイナリ（bblanchon/pdfium-binaries、BSD-3）を取得する。
3. サードパーティ依存を増やさず、PNG書き出し用のミニマルエンコーダ（`image_io.h/.cpp`、zlib storedブロックによる非圧縮PNG）を新規実装する。
4. `PdfBackend::render_page_at_dpi` にクロップ矩形パラメータを追加する（Python版のエクスポート時クロップに相当）。
5. `WorkingDocument` に `rotate_many`（複数ページ一括回転・単一undoステップ）、`rebase_all_pages_to`（上書き保存後の内部再割当）、`clear_undo_history`（ページは保持したままundo履歴のみクリア）を追加する。
6. Python版 `PDFManager` と同等のAPIを持つ `PdfManager` クラスを新規実装する（`load_pdfs`/`page_infos`/`reorder_pages`/`rotate_page(s)`/`delete_pages`/`undo`系/`can_overwrite_source`/`overwrite_source`/`save_as`/`export_pages_to_images`/`close_document`/`close_all`）。
7. `tests/test_pdf_manager.py` の26件に対応する形で `PdfManager` 向けのテストを `engine_tests.cpp` に追加し、既存20件と合わせて全件passするまでビルド・実行のループを回す。
8. `build_native.py` を、`engine.cpp` が新たに `pdf_backend.cpp`/`image_io.cpp` に依存するようになった点に合わせて更新する。

## 6. 検証方法

- `core/native/`で `engine.cpp pdf_backend.cpp image_io.cpp engine_tests.cpp` をビルドし、生成された実行ファイルの終了コードが0であることを確認する。
- `build_native.py` の `build_tests()` を実行し、公式ビルド経路でも同様に全passすることを確認する。
- **重要**: ビルド・実行はPowerShell経由で行う。git-bash経由でPythonから`subprocess`でこの実行ファイルを起動すると、環境依存で`STATUS_STACK_BUFFER_OVERRUN`（0xC0000409）により確実にクラッシュすることを確認した（コード自体の欠陥ではなく、MSYS2/git-bashのプロセス生成がネイティブWin32コンソールアプリの起動に干渉する既知の類の問題）。詳細は実施結果に記載。
