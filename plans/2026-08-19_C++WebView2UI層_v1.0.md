# C++ WebView2 UI層 計画書 v1.0

作成日: 2026-08-19
前提: [`plans/2026-08-19_C++コア再構築_結果_v1.0.md`](2026-08-19_C++コア再構築_結果_v1.0.md)でエンジン層のテストが全pass。ユーザーより「目的達成まで進めて」と継続の指示を受け着手。

## 1. 目的・背景

前回のC++移植が実際に失敗したのはこの層である（[`CPP_PORT_POSTMORTEM.md`](../CPP_PORT_POSTMORTEM.md)）。エンジン層の自動テストはUIの正しさを何も保証しないため、ここではポストモーテムの核心的教訓——**「実際にアプリを起動し、実物のマウス・キーボードで操作して動作を確認する」**——を、今回は自動テストの代わりに自分の目でスクリーンショットを確認する形で実践する。

## 2. 現状（着手前）

- git履歴に829行の `webview_main.cpp`（WebView2ホスト、ダイアログ、COMコールバック手書き実装）と、162行の `app.js` + 33行の `index.html` + 24行の `style.css` が残っていた。
- ポストモーテムの技術メモが挙げる既知の落とし穴のうち、`webview_main.cpp` 側は概ね対処済みだった（`EventRegistrationToken`、`OleInitialize`、`AttachThreadInput`、MinGWでの手書きCOMコールバック）。
- **ただし1点、ポストモーテムが名指しで警告していた問題が未修正のまま残っていた**: `dispatch_message()` がメッセージ全文に対する部分文字列検索（`message.find(L"open_pdf")` 等）でリクエスト種別を判定していた。ファイルパスに命令名と同じ文字列が含まれると誤爆しうる。
- フロントエンド（`app.js`/`index.html`/`style.css`）はポストモーテムが「Python版に無い、誰も指示していないUI」と名指しした状態のまま（サムネイル項目内の↑/↓/回転/削除ボタン、プレビュー未実装、固定サイズ）だった。

## 3. 変更方針

1. `webview_main.cpp` の部分文字列マッチを修正し、`"type"` キーの値のみで分岐する。
2. グローバルな `WorkingDocument` + パスワードmapの直接操作をやめ、新規実装済みの `PdfManager` を使うよう書き換える。
3. `main.py` のCLI引数バイパスと同じ仕組みをC++側にも用意する（コマンドライン引数のPDFパスを、WebView2の初回ナビゲーション完了後に自動で開く）。ダイアログ自動化には頼らない。
4. フロントエンドをPython版の実際のUI構造（サムネイル項目にボタンを持たせない、フラットな一覧、ファイル名タグ、ページ番号、右側プレビュー、ドラッグ&ドロップ並べ替え）に合わせて書き直す。
5. `build_native.py` でGUI版・CLI版をビルドし、実際にウィンドウを起動、コマンドライン引数でPDFを渡し、スクリーンショットを撮って自分の目で確認する。

## 5. 検証方法

- `build_native.py` でGUI版・CLI版をビルドし、コンパイルエラーが無いことを確認する。
- 実際に `QuickMarkPDF.exe` を4ページのテストPDFパス付きで起動し、PowerShellの `System.Drawing` でウィンドウ全体をスクリーンショットし、Readツールで自分の目で確認する。
- 開く（CLI引数）→ページ選択→プレビュー表示→回転→削除→元に戻す、の一連の操作を実際にマウスクリックで再現し、各段階でスクリーンショットを撮って確認する。
- 「テストがpassした」ではなく「実際に動いているところを見た」ことを完了の根拠とする。
