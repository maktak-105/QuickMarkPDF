# 計画書: サムネUI改善と設定機能追加（v1.1）

v1.0からの変更点：「縦スクロール」モード時の拡大縮小手段を、Ctrl+ホイール案からユーザー指定の「右クリック押しっぱなしで上下ドラッグ」案に変更（Cのみ変更、他は v1.0 のまま）。

## 目的
サムネパネルの初期表示の余白バグを修正し、マウスホイール挙動を選べる「設定」機能を新設、ツールバーのレイアウト（2段化・ボタン幅統一）を整える。

## 現状分析

### 1. サムネ「小→中」で余白が縮む問題（原因特定済み）
- [thumbnail_panel.py:139-152](../src/pdf_editor/ui/thumbnail_panel.py:139) `_apply_size("medium")` は `_panel_width = w + 2*_INDENT + 24` を計算する（medium で **184px**、実測・DPI=1.0環境）。
- 起動直後の初期値としては [main_window.py:274](../src/pdf_editor/ui/main_window.py:274) で `splitter.setSizes([thumbnail_panel._panel_width, 1000])` が一度呼ばれ、この時点では正しく184pxになる。
- しかし、PDFを開くと必ず [main_window.py:656,738](../src/pdf_editor/ui/main_window.py:656) で `_set_mode("pdf")` が呼ばれ、[main_window.py:419-432](../src/pdf_editor/ui/main_window.py:419) の中で
  ```python
  left_width = max(220, self._last_pdf_panel_width or self.thumbnail_panel._panel_width)
  ```
  が実行される。`self._last_pdf_panel_width` は [main_window.py:182](../src/pdf_editor/ui/main_window.py:182) で **`320`固定のハードコード初期値**になっており、Markdown⇔PDFモード切替を一度もしていないセッションでは常にこの`320`が使われてしまう。
  → 実測で確認済み：起動してPDFを開いた直後は `splitter.sizes() == [320, ...]`（本来のmedium幅184pxより136px広い＝これが「余白が大きい」の正体）。
  → その後ユーザーが「小」→「中」とツールバーボタンで切り替えると、[main_window.py:1255-1266](../src/pdf_editor/ui/main_window.py:1255) の `set_thumbnail_size()` が正しく `_panel_width`（184px）で再計算するため、そこで初めて余白が正しいサイズに縮む。
- **つまりバグの本体は「320というハードコードされたダミー初期値」であり、`_panel_width`の計算式自体には問題がない。**

### 2. 設定メニュー
- 現状、メニューバー（`QMenuBar`）は存在しない（ツールバーのみ）。`grep`で`menuBar`/`addMenu`はヒットなし。
- 設定の永続化には既に `QSettings("pdf-editor", "PDFEditor")` を使っている（[main_window.py:200](../src/pdf_editor/ui/main_window.py:200)、`window/geometry` `paths/last_used_dir` `thumbnails/size` を保存済み）。同じ仕組みに新しいキーを追加する形で実装する。

### 3. マウスホイール挙動 / 右ドラッグ挙動
- [main_window.py:768-805](../src/pdf_editor/ui/main_window.py:768) `eventFilter()` で、プレビュー領域のホイールは**常に拡大縮小**（縦スクロールは常にブロック）、右クリック押しっぱなし＋ドラッグは**常にパン**（表示位置move）の実装になっている。
- 縦スクロールモードを選ぶ手段は現状ない。

### 4. ツールバー
- [main_window.py:500-586](../src/pdf_editor/ui/main_window.py:500) `_create_toolbar()` で単一の`QToolBar`に全ボタン（開く／PDF切り出し／画像出力／回転3種／保存／サムネサイズ3種）が一列に並んでいる。
- ボタンは`QAction`から自動生成される`QToolButton`（`ToolButtonTextUnderIcon`）で、文字幅に応じて自動サイズされるため、「開く」「保存」（2文字）は「画像出力」（4文字）より狭い。

## 変更内容

### A. 初期余白バグの修正（[main_window.py](../src/pdf_editor/ui/main_window.py)）
- `self._last_pdf_panel_width = 320` → `self._last_pdf_panel_width = None` に変更（未リサイズ状態を表す）。
- `_set_mode()`の該当行はそのまま（`or self.thumbnail_panel._panel_width`のフォールバックが効くようになる）。
- 影響範囲：起動時・PDF初回オープン時の左ペイン幅のみ。Markdown⇔PDF切替時に前回幅を覚えておく既存の挙動（`_last_pdf_panel_width`をその都度更新する部分）は変更しない。

### B. 「設定」メニューの追加（[main_window.py](../src/pdf_editor/ui/main_window.py)、新規 `src/pdf_editor/ui/dialogs/preferences_dialog.py`）
- `QMenuBar`を新設し、「設定」メニュー→「環境設定...」アクションを追加。
- `PreferencesDialog`（`ExportDialog`と同様の`QGroupBox`+`QRadioButton`構成）を新規作成し、以下を設定：
  - **マウスホイール操作**：「拡大・縮小（既定）」／「縦スクロール」のラジオボタン。
- 選択内容は`QSettings`に`preview/wheel_mode`（値: `"zoom"` / `"scroll"`、既定 `"zoom"`）として保存、即時反映（ダイアログ閉じたら再起動不要で適用）。

### C. ホイール／右ドラッグ挙動の切り替え実装（[main_window.py](../src/pdf_editor/ui/main_window.py) `eventFilter()`）※v1.1で変更

**`preview/wheel_mode == "zoom"`（既定）：現状のまま変更なし**
- ホイール：拡大縮小
- 右クリック押しっぱなし＋ドラッグ：パン（表示位置移動）

**`preview/wheel_mode == "scroll"`（新規）：**
- ホイール：通常の縦スクロール（`event.accept()`せず`QScrollArea`のデフォルト処理に委ねる）
- 右クリック押しっぱなし＋ドラッグ：**パンではなく拡大縮小に切り替える**。下方向にドラッグで拡大、上方向にドラッグで縮小（押している間、ドラッグ量に応じてリアルタイムに倍率が連続変化。離すと確定。既存のパン処理と同じ「押す→動かす→離す」の3イベントを使い、`current_zoom`をドラッグ量から計算する形に置き換える）。

つまり、**「拡大縮小の主手段」と「パン／スクロールの主手段」を、wheel_modeの設定によって役割ごと入れ替える**形になる：
| | zoomモード（既定） | scrollモード |
|---|---|---|
| ホイール | 拡大縮小 | 縦スクロール |
| 右ドラッグ | パン | 拡大縮小（下=拡大／上=縮小） |

- **確認したい点**：scrollモードを選ぶと右ドラッグでのパンができなくなる（拡大縮小に専有されるため）。ズームした後の左右位置調整は水平スクロールバーのみになるが、この仕様で問題ないか。

### D. ツールバーの2段化（[main_window.py](../src/pdf_editor/ui/main_window.py) `_create_toolbar()`）
- 1段目：開く／PDF切り出し／画像出力／右90°／左90°／180°／保存
- `self.addToolBarBreak(Qt.TopToolBarArea)` で改行し、2段目に分離した`QToolBar`：サムネ ラベル／小／中／大
- 見た目・操作対象は変更なし（配置のみ変更）。

### E. ボタン幅の統一（[main_window.py](../src/pdf_editor/ui/main_window.py) `_create_toolbar()`）
- ツールバー構築後、`toolbar.widgetForAction(self.img_export_action)`の`sizeHint().width()`を基準幅として取得。
- `open_action`・`save_action`に対応する`QToolButton`に同じ`minimumWidth`を設定し、見た目の幅を「画像出力」に揃える。
- 対象は「開く」「保存」の2つのみ（「PDF切り出し」「回転」系ボタンは今回のスコープ外・変更しない）。

## 変更しないもの
- サムネイルの描画ロジック・D&D・Undo・保存周りのコアロジックは一切変更しない。
- 既存のQSettingsキー（`window/geometry` `paths/last_used_dir` `thumbnails/size`）の意味・挙動は変更しない。
- zoomモード（既定）での右ドラッグ＝パンの挙動は変更しない。

## 検証方法
1. `dist/PDF_Editor/PDF_Editor.exe`を再ビルド。
2. アプリ初回起動（QSettingsをクリアした状態）→ PDFを開く → サムネパネルの左右余白が「小→中」切替後と同じ幅（狭い方）で最初から表示されることをスクリーンショットで確認。
3. メニューバーに「設定」→「環境設定...」があり、ダイアログでホイール操作を切り替えられることを確認。
4. 「拡大・縮小」（既定）選択時：従来通りホイールで拡大縮小、右ドラッグでパンできることを確認。「縦スクロール」選択時：ホイールで縦スクロール、右クリック押しっぱなし下ドラッグで拡大・上ドラッグで縮小できることを確認。設定はアプリ再起動後も保持されることを確認。
5. ツールバーが2段（アクション行／サムネサイズ行）になっていることを目視確認。
6. 「開く」「保存」ボタンの幅が「画像出力」ボタンと揃っていることを目視確認。
7. 既存の自動テスト（`tests/`配下）が全て通過することを確認。

## リスク
- `_last_pdf_panel_width`の初期値変更は影響範囲が小さいが、万一他の箇所で`320`という値に暗黙依存していないか実装時に再確認する（現状のgrep結果ではA以外に依存箇所なし）。
- ツールバーを2段にする際、`QMainWindow`のツールバー領域の高さが増えるため、プレビュー領域が僅かに縮む（許容範囲と判断）。
- scrollモードでは右ドラッグによるパンが使えなくなる（上表の通り拡大縮小に専有されるため）。水平方向の位置調整は水平スクロールバーのみになる。この仕様で問題なければそのまま進める。
