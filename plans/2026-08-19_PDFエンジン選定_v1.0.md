# PDFエンジン選定調査 v1.0

作成日: 2026-08-19
対象アプリ: QuickMarkPDF
対象: `PdfBackend`（`core/native/pdf_backend.h/.cpp`）の暫定実装を正式エンジンへ差し替える前段の比較調査

`2026-08-18_C++移植_v1.0.md` 3節で保留していた「MuPDF C APIを第一候補、ライセンス確認後に問題があればPDFium等と比較」を実施した結果。

## 1. 前提となる制約

- QuickMarkPDFは `LICENSE`（MIT）でソース公開し、`dist/binary/` へビルド済みEXEを配布する運用（QuickFolderSize等、同ワークスペースの他アプリと同じ配布モデル）
- `2026-08-18_C++移植_v1.0.md` Phase 0で「MITライセンスで配布可能な依存構成を確定」が明記されている
- → 依存ライブラリはMIT配布・EXE同梱を妨げないライセンスであることが必須条件

## 2. MuPDF

- ライセンス: **AGPL v3 / Artifexとの商用ライセンスのデュアルライセンス**
  - AGPLで使う場合、MuPDFをリンクしたソフトウェア全体をAGPLで公開する義務が生じる（ネットワーク経由の提供も対象）
  - MITライセンスでのEXE配布と両立しない。商用ライセンスは有償（要見積り、一般に高額）
- 技術面: C API、CMakeで標準的にビルド可能、AES-128/256の読み込み・保存に対応、CJKフォールバックフォント（Source Han Serif等）内蔵、pdfwriteでページ編集・保存に対応
- 結論: 技術要件は満たすが、**ライセンスがMIT配布モデルと非互換**

## 3. PDFium

- ライセンス: **BSD 3-Clause（許諾型）**
  - Chromium/Chromeで採用。商用アプリへの組み込み・非公開配布に制限なし
- 技術面: C/C++ API（`FPDF_*`）でページ読み込み・回転・削除・並べ替え・保存（`FPDF_SaveAsCopy`等）に対応。暗号化PDF（RC4/AES）の読み込みに対応。CJKはICUデータ/フォントの同梱が必要（配布時にデータファイルを含める運用が必要）
- ビルドの難点: 本家はdepot_tools + gclient + GN + Ninjaという Chromium 由来のビルド基盤が必須で、CMake/MinGWでは直接ビルドできない
- 回避策: **`bblanchon/pdfium-binaries`**（BSD-3、GitHub公開、毎週自動ビルド）がWindows x64向けの**ビルド済み共有ライブラリ（`pdfium.dll` + ヘッダ）**を配布しており、depot_toolsを使わずに導入可能。既存の `third_party/webview2/` と同じ「ビルド済みバイナリをthird_partyへ配置しGit管理外にする」運用パターンがそのまま使える

## 4. 比較表

| 項目 | MuPDF | PDFium |
|---|---|---|
| ライセンス | AGPL/商用デュアル | BSD-3（許諾型） |
| MIT配布EXEとの互換性 | 不可（商用ライセンス購入なら可） | 可 |
| ビルド | CMake単体で容易 | 本家は困難、`pdfium-binaries`で回避可 |
| 暗号化PDF | AES-128/256 読み書き対応 | RC4/AES 読み込み対応 |
| CJK | フォールバックフォント内蔵 | ICU/フォント同梱が別途必要 |
| ページ編集・保存API | 豊富（pdfwrite） | `FPDF_EDIT`/`FPDF_SaveAsCopy`で対応 |

## 5. 結論・推奨

**PDFiumを採用する。** 根拠はライセンスの一点に尽きる。MuPDFは技術力で上回るが、AGPLはQuickMarkPDFのMIT配布モデルと相容れず、商用ライセンス購入は本プロジェクトの前提にない。

導入方法は `bblanchon/pdfium-binaries` のWindows x64ビルド済み `pdfium.dll` を `third_party/pdfium/` へ配置し、`scripts/fetch_webview2_sdk.ps1` と同様の取得スクリプトを用意する。

（訂正）配布アーカイブを実際に展開して確認した結果、`pdfium-win-x64.tgz` に別体の `icudtl.dat` は含まれておらず、ICUデータは `pdfium.dll` へ静的に埋め込まれている（`is_component_build=false` ビルド）。CJK対応のために別ファイルを同梱する必要はない。
