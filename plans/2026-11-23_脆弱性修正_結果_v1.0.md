# 結果: 脆弱性修正 (v1.0)

対応する計画書: `plans/2026-11-23_脆弱性修正_v1.1.md` (承認済み。v1.0 は旧版)
元になった診断: `docs/investigations/2026-11-23-security-audit.md`
実施日: 2026-11-23

## 結論
診断書の V-1〜V-4、S-1〜S-6、B-1〜B-3 のうち、コードで解決できるものはすべて修正した。コード署名と CFG は計画どおり対象外。
悪意ある `.md` を開いて別の PDF を開くと、確認なしで任意の場所へ画像が書き込まれる攻撃 (診断時に実バイナリで再現) は、新しいビルドでは成立しない。旧ビルドでは同じテストで成立することを対照として確認した。
commit / push はしていない。`dist` の exe は新ビルドに置き換えた。

## 実施内容 (診断書の ID 順)

### V-1 Markdown XSS と防御層
- 新規 `src/ui/js/markdown.js`: 変換処理を `app.js` から切り出した。DOM 非依存なので Node でテストできる。
  - `escapeHtml` が `"` と `'` も処理する。数式 `$…$` / `$$…$$` の中身は復元時にエスケープする。
  - リンクは `http:` / `https:` / `mailto:` / `#…`、画像は `http:` / `https:` / base64 のラスター `data:` のみ許可 (SVG は不可)。それ以外はリンク・画像にせず文字で表示する。
  - 処理順は「コード → 画像 → リンク → 強調」で、生成したタグをプレースホルダに退避する (強調の正規表現が属性値に触れない)。
- `app.js`: 変換を `markdown.js` に委譲。Mermaid は `securityLevel: 'strict'`。
- `scripts/bundle_html.py`: `markdown.js` を取り込み、CSP の `<meta>` を生成する。インライン script の SHA-256 は自動計算。
  - `default-src 'none'; script-src 'self' <ハッシュ>; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`
- `main_gui.cpp`: `WebMessageReceived` で送信元がアプリ自身のときだけ処理する。`NavigationStarting` でアプリ以外への遷移を拒否する。`NewWindowRequested` は常に処理済みにし、`http(s)` と素の `mailto:` だけを既定のアプリで開く。ハンドラが例外を投げてもアプリが落ちないよう、メッセージ処理を `try/catch` で囲んだ。

### V-2 画像出力の出力先検証
- `engine.cpp`: `PdfManager::is_safe_export_prefix` と `plan_export_image_paths` を追加。接頭辞にファイル名に使えない文字・区切り文字・制御文字・100 バイト超があれば何も書かない。出力先フォルダも作らない。
- `main_gui.cpp` の `handle_export_images`: dpi は 1〜1200、`output_dir` は絶対パスのみ (デバイスパス拒否)。ネイティブが決めた/ユーザーが確認済みのフォルダ以外、または既存ファイルを上書きする場合は、ネイティブの確認ダイアログを出す。

### V-3 暗号化 PDF
- `PdfDocumentInfo::encrypted` と `PdfManager::has_encrypted_sources()` を追加 (pdfium の `FPDF_GetSecurityHandlerRevision`。オーナーパスワードのみの PDF も検出)。
- 保存時は、暗号化ソースを含むと上書き保存を選べず、「暗号化は保持されません」の警告 (続行/キャンセル) を出して新規保存のみにする。PDF 切り出しにも同じ警告。

### V-4 WebView2 の絞り込み
- DevTools とブラウザ固有キーを無効化。ステータスバーと標準の右クリックメニューは残した (ユーザー判断)。

### S-1〜S-6
- S-1: `render_page` の幅は 4096 まで、総ピクセル 64M 超は縮小。書き出しは dpi 1200 まで、150M ピクセル超のページはエラー。メッセージの数値は飽和処理 (オーバーフローしない)。Markdown の追加読み込み行数も 20000 に制限。
- S-2: `QUICKMARKPDF_ENABLE_TEST_API` でテスト用コード一式を囲んだ。製品ビルドは含まない。`python scripts/build.py testapi` で検証用ビルドを作る。テスト用ビルドのみ、受信バッファ上限・`SO_EXCLUSIVEADDRUSE`・検証用コマンド (`ui_message`、`eval_js`、`get_webview_settings` 等) を追加。
- S-3: `pdfium.dll` を exe と同じフォルダのフルパスで読み込む。起動時に `SetDefaultDllDirectories` を呼ぶ。
- S-4: 一時ファイル名を乱数付きにし、`MoveFileExW` で置き換える。失敗時は元ファイルを残す (旧版の `copy_file` フォールバックは廃止)。
- S-5: CredUI のバッファ、受け取ったパスワード文字列、`known_passwords_`、pdfium キャッシュのパスワードを `SecureZeroMemory` で消去する。
- S-6: WebView2 のプロファイルを `%LOCALAPPDATA%\QuickMarkPDF\WebView2` に移した。初回のみ旧 `%TEMP%` の localStorage をコピーする。

### B-1〜B-3
- B-1: `fetch_pdfium.ps1` / `fetch_webview2_sdk.ps1` に SHA-256 の固定値と検証を追加 (検証に通ったときだけ `third_party` を置き換える)。固定値は今回取得したアーカイブの値 (初回信頼)。
- B-2: `codeql.yml` に `javascript-typescript` を追加。
- B-3: 3 つのワークフローの Actions をコミット SHA で固定。`choco` は直近の成功した CI のログのバージョン (mingw 16.1.0、python 3.15.2) で固定。`ci.yml` に Node のテストと `testapi` のコンパイル確認を追加。`release.yml` に Node のテストと来歴証明 (`actions/attest-build-provenance`) を追加。ビルドに `-fstack-protector-strong`、`-D_FORTIFY_SOURCE=2`、`-Wl,--dynamicbase,--nxcompat,--high-entropy-va` を追加。

### 追加・変更したファイル
- 新規: `src/ui/js/markdown.js`、`src/engine/secure_wipe.h`、`tests/markdown_render_test.js`、`tests/e2e/security_regression.py`
- 変更: `src/app/main_gui.cpp`、`src/engine/{engine,pdf_backend}.{h,cpp}`、`src/engine/test_api_server.cpp`、`src/ui/js/app.js`、`scripts/{build.py,bundle_html.py,fetch_pdfium.ps1,fetch_webview2_sdk.ps1}`、`.github/workflows/*.yml`、`tests/engine_tests.cpp`、`docs/environment.md`、`docs/environment_jp.md`

## 検証結果 (実際に実行して確認したもの)
1. **Node テスト** `node tests/markdown_render_test.js`: 11 項目すべて成功。診断時の攻撃を含む攻撃文字列 50 件超と、30,000 件のランダム入力が、いずれも出力検証器 (許可タグ・属性・URL スキームのみ) を通った。
2. **旧実装との比較**: 旧実装に同じ攻撃文字列を通すと、スクリプト実行可能な出力になる (テストが有効であることを確認)。リポジトリの `.md` 54 件のうち 29 件は完全一致、25 件に差。差はすべて意図した変更で、次の 2 種類だった。
   - 相対パスのリンク (`docs/about.md` 等) がリンクでなく文字になった。アプリ内では元々開けないリンク。
   - コードスパン内の `*` や `__init__` が正しく表示されるようになった (旧版は `<em>` / `<strong>` が混ざって HTML が壊れていた)。
3. **ブラウザ検証** (実 UI を埋め込んだ HTML、仮ブリッジ): 診断時の PoC が実行されず、盗聴用リスナーも付かない。CSP 単体でも、インラインのイベントハンドラ、注入した script 要素、`javascript:` URL が遮断された。通常の文書では Mermaid 2 図・MathJax 3 式・表・リンクが描画され、CSP 違反はゼロ。Mermaid `strict` で `javascript:` リンクと HTML ラベル内の `onerror` が動かない。画面の見た目も目視で確認した。
4. **エンジンテスト** `python scripts/build.py test` (`build.py all` 内でも実行): 追加分 (prefix 拒否、パス計画、上限、暗号化検出、暗号化の上書きで非暗号化になること、上書き失敗時に元ファイルが残ること) を含め全件成功。
5. **実バイナリの回帰テスト** `tests/e2e/security_regression.py` (テスト用ビルド、実 WebView2): 全チェック成功。
   - V-1: 悪意ある `.md` を開き、その後 PDF を開いてもファイルが書かれない。旧ビルドでは書かれる (対照)。
   - V-2: `ui_message` 経由で、`../` と絶対パスの prefix、相対・デバイスパスの出力先、dpi 2000 がすべて拒否され、正常な書き出しは動く。
   - V-1/V-4 (WebView2 内): CSP が注入されたインラインハンドラを止める。別サイトへの遷移はキャンセルされる。`window.open(https)` は既定ブラウザ向けに渡され、`file:` と `javascript:` は破棄される。DevTools とブラウザ固有キーは無効で、ステータスバーと標準メニューは有効のまま。MathJax / Mermaid が CSP 下で描画され違反ゼロ。
   - S-3: 現在のフォルダに置いた `pdfium.dll` (無害なマーカー DLL) は、新ビルドではロードされず、旧ビルドではロードされる (対照)。`SetDefaultDllDirectories` を入れても WebView2 は正常に起動する。
   - S-6: 新しい場所にプロファイルが作られ、旧 `%TEMP%` の localStorage がコピーされる。
6. **製品ビルド** `python scripts/build.py all`: 成功し `dist` を更新。`dist/QuickMarkPDF.exe` にはテスト用の文字列 (`QUICKMARKPDF_TEST_PORT` 等) と `ws2_32` が無く、テスト用コマンドのコードも含まれない。ASLR / DEP / HighEntropyVA は有効のまま。`pdfium.dll` と `WebView2Loader.dll` は、ハッシュ固定した配布元アーカイブ内のものと一致する。
7. **取得スクリプト**: ハッシュを誤った値にすると中断し、`third_party` を壊さない。固定外のバージョンはハッシュなしで拒否する。固定した 2 つのハッシュは再取得した値とも一致した。
8. **ワークフロー**: YAML の構文確認済み。`uses:` はすべて 40 桁の SHA 固定。SHA は GitHub API で取得した。

## 計画との差異
- V-4 の設定は、計画 v1.1 では「テスト用ビルドには設定しない」としたが、実際に設定値を検証するため、製品とテスト用の両方に設定した。検証したのは製品と同じ設定になる。
- 計画外の追加 (いずれも小さく、同じ目的): メッセージ処理の例外ガード、Markdown 追加読み込み行数の上限、`build.py` の `QUICKMARKPDF_DIST` (出力先の切り替え)、`docs/environment*.md` へのテスト手順の追記。
- `mailto:` は素のアドレスのみ開く (クエリ付きは破棄)。

## 未検証 (自動では確認できていない)
- V-3 の警告ダイアログと V-2 の確認ダイアログの実画面 (モーダルのため)。V-3 は述語 (`has_encrypted_sources`) のテストとコード確認まで。
- S-5 のメモリ消去 (コード確認のみ。`std::string` のコピーすべては追跡できない)。
- V-4 の実際の効き方: F5 / Ctrl+P が効かないこと、アプリ独自のショートカット (Ctrl+O、Ctrl+S、Ctrl+Z、Delete、矢印) が動くこと、右クリックの標準メニューに「印刷」が出て使えること。手動確認をお願いします。出ない場合は対応を相談します。
- 実際の `ShellExecute` でのブラウザ起動 (テスト用ビルドは記録のみ)、ユーザー操作によるリンクのクリック。
- **CI 上の動作** (CodeQL の JavaScript 解析、SHA 固定後のワークフロー、`choco` の固定バージョン、`-fstack-protector-strong` が CI の MinGW でリンクできるか、来歴証明は次回タグのリリースで初めて動く、Node が runner にあること)。
- MathJax 3.2.2 の `\require` 経由の拡張 (`\href` 等) は検証していない。ただし数式の中身はエスケープ済みで、CSP が `javascript:` を止める。

## 残課題・副次的に見つけた不具合 (今回は未修正)
1. **暗号化 PDF は、パスワードで開いたあとの描画・テキスト取得が失敗する** (旧・新ビルドとも確認済み)。`render_page` / `get_text_layout` がパスワードを渡さないため `password required` になる。V-3 とは別の機能不具合。
2. **「上書き保存」のあと、pdfium のキャッシュが古いまま**で、並べ替えて上書きしたあとの 0 ページ目が古い内容のまま (旧・新ビルドとも確認済み)。
3. ローカルの `main` は `origin/main` (v4.3.0) より 1 コミット遅れている。v4.3.0 はバージョン表記と CSS の背景調整のみで、今回触ったファイルとの重複はない。診断・修正は v4.2.0 のローカルが基準。
4. 対象外のまま: 配布物のコード署名 (証明書または SignPath の承認が必要)、CFG (MinGW が非対応)。
5. バージョン番号 (4.2.0)、`HISTORY.md`、commit / push は未実施。

## 利用者に見える挙動の変更
- Markdown: 相対パスの画像・リンクと `javascript:` 等のリンクは表示されない。リンクは新しいウィンドウでなく既定ブラウザで開く。
- 画像出力: 手入力したフォルダ、または既存ファイルを上書きする場合は、確認ダイアログが出る。
- 暗号化 PDF: 上書き保存はできず、警告のうえ新規保存のみ。
- F12、Ctrl+P、F5、Ctrl+R、Ctrl+F は使えない。
