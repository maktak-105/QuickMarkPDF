# 結果報告: 技術的負債解消（v1.0）

対応する計画書: [2026-07-09_技術的負債解消_v1.0.md](2026-07-09_技術的負債解消_v1.0.md)

## 実施内容

### 1. dialogs/*.py の重複解消
- [dialogs/export_dialog.py](../src/pdf_editor/ui/dialogs/export_dialog.py) を main_window.py 版（クロップ範囲出力対応あり）の内容で上書き。
- [dialogs/header_footer_dialog.py](../src/pdf_editor/ui/dialogs/header_footer_dialog.py) は元々同一内容だったため変更なし。
- [main_window.py](../src/pdf_editor/ui/main_window.py) から `HeaderFooterDialog` / `ExportDialog` の重複定義（約320行分）を削除し、`from src.pdf_editor.ui.dialogs import HeaderFooterDialog, ExportDialog` に置き換え。
- 併せて不要になった `QGroupBox` 等のQt Widgetインポートを整理（`QDialog`・`QInputDialog` は使用箇所があるため維持）。

### 2. print → logging 統一
- [pdf_manager.py](../src/pdf_editor/pdf/pdf_manager.py)：`logger = logging.getLogger(__name__)` を追加し、3箇所の `print()` を `logger.error()` に置換。
- [thumbnail_panel.py](../src/pdf_editor/ui/thumbnail_panel.py)：同様に1箇所を `logger.warning()` に置換。
- [main.py](../main.py)：`main()` 冒頭に `logging.basicConfig(level=logging.INFO, format=...)` を追加し、コンソールにログが出力されるようにした。

### 3. HF重ね書きバグ修正
- [pdf_manager.py](../src/pdf_editor/pdf/pdf_manager.py) に `_reload_pages_from_disk()` を新設。`remove_header_footer()` の「元ファイル再読込＋回転再適用」ロジックをここに集約。
- `add_header_footer()` の冒頭で必ず `_reload_pages_from_disk()` を呼んでからテキストを挿入するように変更。これにより、ダイアログを再度開いて設定を変えて「適用」しても、古いヘッダー/フッターの文字が残らず、常に最新の設定のみが反映される。
- `remove_header_footer()` は `_reload_pages_from_disk()` を呼ぶだけに簡潔化（外部から見た挙動は変更なし）。
- 回帰テスト `test_add_header_footer_can_be_reapplied_without_stacking` を [tests/test_pdf_manager.py](../tests/test_pdf_manager.py) に追加。「DRAFT」→「FINAL」と2回適用し、保存後のテキストに「FINAL」のみ含まれ「DRAFT」が残っていないこと、ページ番号footerが重複していないこと（`"1 / 2"` の出現回数が1回）を検証。

### 4. workers.py の実配線
- `main_window.py` に汎用ヘルパー `_run_in_background(func, on_success, on_error, busy_message)` を追加。
  - 多重実行防止（`self._busy` フラグ）
  - 実行中はツールバー＋中央ウィジェット（サムネイル・プレビュー）全体を無効化（`_set_ui_busy`）— バックグラウンドスレッドが `pdf_manager` を操作している間、UIスレッドから同時にアクセスされるのを防止するため
  - `Worker` インスタンスを `self._active_worker` に保持しGCを防止
  - 失敗時は `logger.error` + `QMessageBox.warning`（呼び出し元が独自の `on_error` を渡さない場合のデフォルト動作）
- 以下をこのヘルパー経由のバックグラウンド実行に変更（成功/失敗時の既存ロジックはそのまま移植）：
  - `open_pdfs`（PDF読み込み）
  - `export_images` / `_on_image_extract_requested`（画像エクスポート）
  - `save_pdf` / `_export_selected_as_pdf`（PDF保存・切り出し保存）
- ヘッダー/フッター適用（`add_header_footer`）は計画通り同期のまま（元の計画書のPhase4方針を踏襲）。

### 5. dirty flag + closeEvent
- `MainWindow.__init__` に `self._is_dirty = False` を追加。
- 以下の成功時に `self._mark_dirty()` を呼ぶよう変更：PDF読み込み成功、ページ並び替え、ページ回転、ヘッダー/フッター適用・削除、ファイルを閉じる。
- `save_pdf` 成功時に `self._mark_clean()`（`_is_dirty = False`）。
- `closeEvent(self, event)` をオーバーライドし、`_is_dirty` が True なら `QMessageBox.question` で確認、「いいえ」で `event.ignore()`。

- `python tests/test_file_close.py` … **2件 全てPASS**。

- `python main.py documents/sample_markdown_preview.pdf` を実際に起動し、バックグラウンド化した読み込みパス（`open_pdfs` → `_run_in_background` → `Worker`）経由でPDFが読み込まれることを確認。約6秒間クラッシュ・例外ログなしで動作継続（プロセスメモリ使用量からWebEngine含め正常起動していることを確認）。

**手動確認が推奨される項目（今回のセッションでは実施していない）**:
- ヘッダー/フッターを実際にGUI上で2回異なる設定で適用し、保存したPDFを目視で確認（自動テストでは検証済みだが、UI上のダイアログ操作からの目視確認は未実施）。
- 大きめのPDF（数十ページ）の読み込み・保存・画像エクスポート中にウィンドウが実際に固まらず、処理完了後に正しく結果が反映されることのGUI上での確認。
- 何か変更した状態でウィンドウを閉じようとした際の確認ダイアログの見た目・「いいえ」でのキャンセル動作。
- PyInstallerでのEXEビルド確認（計画書通り本プランでは必須としていない）。

## 残課題・今後の検討事項

- HF修正により `add_header_footer` は呼び出しのたびに全ドキュメントを閉じて再読込するようになったため、ファイル数・ページ数が非常に多いケースでは体感速度がやや低下する可能性がある。今回は同期処理のまま据え置き（計画書の想定通り）。気になる場合は将来的に非同期化を検討。
- `closeEvent` の確認対象はPDF編集操作のみ。Markdownプレビュー→PDF変換の未保存状態はdirty flag管理の対象外（既存動作のまま）。
- `main.py` の `resource_path` と `utils/resources.py` の `resource_path` の重複、および `main_window.py._load_icon` と `utils/resources.get_icon` の重複は、今回の計画スコープ外のため未対応（別途対応が必要であれば追って計画書を作成）。
