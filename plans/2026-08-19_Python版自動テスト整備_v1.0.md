# Python版自動テスト整備 計画書 v1.0

作成日: 2026-08-19
対象バージョン: Python/PySide6版（`python/`）

## 1. 目的・背景

C++/WebView2移植は[`CPP_PORT_POSTMORTEM.md`](../CPP_PORT_POSTMORTEM.md)の通り失敗し、成果物を破棄した。
今後は `python/`（PySide6版）を仕様の正とする。同ポストモーテムが名指しした失敗要因は2つ:

1. 「ビルドが通る・自動テストが通る」を完了の根拠にしてしまい、実操作確認をしなかった。
2. `QFileDialog` 等のネイティブダイアログを自動化に頼って検証しようとし、何十回も操作が止まった。

C++実装を再開する前に、この2つを構造的に防ぐ自動テストプログラムをPython版に対して整備する。
**この自動テストプログラムが完成するまで、C++実装には着手しない。**

## 2. 現状

- `tests/` に6本の `unittest.TestCase` ベースのテストが既にあり、`PYTHONPATH=python` 設定下で37件全てpass（オフスクリーンQPA使用）。
- `pytest` 系ツールチェイン・`pyproject.toml`・`conftest.py` は存在しない。
- `QFileDialog`/`QMessageBox`/`QInputDialog`/`QDialog.exec()` の呼び出し箇所は `main_window.py` に多数存在するが（`open_documents`/`open_pdfs`/`_export_selected_as_pdf`/`_save_markdown_as_pdf`/`_ask_overwrite_or_save_as`/`export_images`/`_save_pdf_as_new_file`/`_confirm_discard_pdf_changes` 等）、いずれもダイアログをガードする共通の仕組みがなく、テストごとに個別モンキーパッチで対処している。
- 見た目（スクリーンショット比較）・体感速度（操作の所要時間）を検証する仕組みは無い。
- 実画面（オフスクリーンでない実ウィンドウ）を使った検証手段も無い。
- `main.py` はコマンドライン引数でPDF/Markdownパスを渡すと `open_documents()` を直接呼ぶため、通常の「開く」操作についてはダイアログを経由せず検証できる（既存6テストが使っている方式）。

## 3. 変更方針

以下の階層でテストプログラムを構成する。

1. **ダイアログガード（最優先）**: `tests/conftest.py` に、`QFileDialog`/`QMessageBox`/`QInputDialog`/`QDialog.exec()` を自動的に監視するオートユースフィクスチャを追加する。テストが明示的に応答を用意しない限り、実際のダイアログを開こうとした瞬間に例外を送出して即座に失敗させる（＝待っても永久にブロックしない）。加えて `pytest-timeout` でテスト単位のタイムアウトを強制し、想定外の要因でイベントループが返ってこない場合も自動テスト全体が止まらないようにする。
2. **単体テスト**: 既存6本を維持しつつ pytest 経由で実行できるようにする（`unittest.TestCase` はpytest互換のためコード変更は不要）。
3. **結合テスト（機能）**: `MainWindow` を実際に生成し、開く/並べ替え/回転/削除/元に戻す/上書き保存/名前を付けて保存/画像エクスポートなど、Python版が持つ操作フローを一通り自動実行して検証する。
4. **見た目テスト**: `QWidget.grab()` でウィジェットのスクリーンショットを取得し、`tests/visual_baselines/` の基準画像とピクセル差分比較する。初回実行時は基準画像を自動生成する。
5. **体感速度テスト**: PDF読み込み・サムネイル生成・回転・並べ替え・エクスポート等の所要時間を計測し、閾値超過や実行結果を `tests/reports/` に記録する。
6. **実画面テスト**: `@pytest.mark.real_screen` を付けた別階層。オフスクリーンQPAを使わず実ウィンドウを表示し、Qtの `QTest` で実際にマウス/キーボードイベントを送って操作し、実画面のスクリーンショットを保存する。既定のテスト実行には含めず、明示的に指定した場合のみ実行する（実行には実デスクトップセッションが必要なため）。
7. **実行手段**: すべてPythonから実行する。`run_tests.py`（リポジトリ直下）が単一の「テストプログラム」入口となり、pytestを呼び出し、pass率・カバレッジ・見た目差分・所要時間をまとめたレポートを `tests/reports/` に出力する。

## 5. 影響範囲

- `python/src/` のプロダクションコードは変更しない（テスト追加のみ）。
- 既存6テストの挙動・pass状態は変えない。
- C++/`core/`関連には一切手を入れない。
- Gitへのpushは指示があるまで行わない。

## 6. 検証方法

- `PYTHONPATH=python .venv/Scripts/python.exe -m pytest tests/ -v`（real_screen除く既定マーカー）が全てpassすること。
- `run_tests.py` を実行し、レポートが `tests/reports/` に生成されること。
- ダイアログガードが実際に「未処理のダイアログ呼び出し」を検出して即時失敗させることを、専用テストで確認する（＝止まって帰ってこない状態を再現させない）。
- 見た目テストは初回実行で基準画像を作成し、2回目の実行で差分ゼロとなることを確認する。

## 7. リスク・懸念

- `QWidget.grab()` はオフスクリーンQPAでもレンダリングされるが、フォント・DPI設定次第で環境間の見た目差分が誤検知になり得る → 差分許容率（閾値）を持たせて厳密ピクセル一致にしない。
- 実画面テストは実行環境（実デスクトップセッション有無）に依存するため、既定実行から除外し、CI/自動巡回では動かさない前提とする。
- 体感速度の閾値はマシン性能に依存するため、厳しすぎる閾値にしてFlakyにしないよう余裕を持たせる。
