# C++移植計画書 v1.0

作成日: 2026-08-18  
対象アプリ: QuickMarkPDF  
対象バージョン: 未リリース

進捗: WebView2全面GUIへ方針変更。C++ページモデル、WebView2ホスト、HTML UI、C++↔JavaScriptメッセージ連携の最小実装とx64ビルド・起動確認を完了。

## 1. 目的・背景

現在のPython + PySide6版を、Windows向けのC++17ネイティブアプリへ段階的に置き換える。Python版は移行期間中の比較対象・動作仕様の基準として残し、機能ごとにC++版の検証が完了してから置き換える。

主な目的は、PySide6/QtWebEngine同梱による配布サイズと起動負荷を減らし、PDF編集コア・UI・Markdown出力をネイティブ実装へ整理することである。

## 2. 目標アーキテクチャ

```text
QuickMarkPDF.exe
├── C++17 + Windows SDK        PDFコア、モデル、Undo、設定
├── WebView2                   UI全体、HTML/CSS/JavaScript
├── PDF engine adapter           PDFの読み込み・保存・ページ操作
├── HTML/CSS/Canvas/SVG         Markdown本文とPDFプレビュー
├── cmark-gfm                   Markdown解析
├── MicroTeX                   数式描画（採用可否を検証）
└── WebView2 WebMessage API     C++とのJSONメッセージ連携
```

PDFエンジンは、既存のPyMuPDFとの機能互換性を優先してMuPDF C APIを第一候補とする。採用前にライセンス（AGPL/商用）と配布条件を確認し、問題がある場合はPDFium等の代替候補を比較する。

## 3. 機能移行の順序

### Phase 0: 仕様と依存関係の固定

- Python版の37テストとサンプルPDFを移行時の比較基準にする
- PDFエンジン、Qt6、WebView2 SDK、cmark-gfmの入手方法を固定
- MITライセンスで配布可能な依存構成を確定

### Phase 1: PDF編集コア

- 複数PDFを単一の作業ドキュメントへ読み込む
- ページ参照、元ファイルタグ、ページ番号を保持
- 並べ替え、ファイル間移動、回転、削除、分割保存
- 新規保存・上書き保存・画像出力
- パスワード付きPDFの扱い
- Undo/Redo、dirty状態、保存失敗のエラー情報

### Phase 2: WebView2 UI

- サムネイル一覧とページプレビュー
- ドラッグ＆ドロップ、複数選択、右クリックメニュー
- 設定、ショートカット、未保存確認をHTML UIへ実装
- Python版と同じ操作結果になる回帰テスト

### Phase 3: Markdown / Mermaid / 数式

- cmark-gfmでMarkdownを解析
- HTML/CSSで本文・表・コードを表示
- C++ PDFエンジンまたはブラウザ印刷でPDFを出力
- 数式はMicroTeXを評価し、難しい場合はSVG変換層を用意
- MermaidはWebView2内でSVGとして描画する

### Phase 4: 配布・置き換え

- `QuickMarkPDF.exe` のReleaseビルド
- WebView2 Runtimeの前提条件とEvergreen/Fixed運用を明記
- `QuickMarkPDF-binary.zip` のフラット配布
- CIでビルド、テスト、配布ファイル存在チェック
- C++版の実機検証完了後にPython版をlegacy扱いへ移行

## 4. 変更対象

| パス | 内容 |

## 5. 今回の着手範囲

- `core/native/` にPDFエンジン非依存の作業ドキュメントモデルを作成
- `core/webview2/` にWebView2 x64ホストを作成
- `ui/` にツールバー、ページ一覧、プレビューの初期画面を作成
- WebMessage APIでC++とJavaScriptのメッセージ往復を実装
- ネイティブファイル選択、PDF検査、ページ数のWeb UI反映を実装
- ページ追加、並べ替え、回転、削除の不変条件をC++で実装
- CTestによる正常系・異常系のネイティブモデル回帰テストを追加
- `QuickMarkPDF_cli.exe demo` でC++コアを実際に実行確認
- `QuickMarkPDF_webview.exe` のx64 Releaseビルドと5秒間の起動を確認
- WebView2からPDF選択メッセージを受け、ページ一覧を更新する経路を実装

ページ数検査は暫定実装であり、正式なPDFエンジン接続時に置き換える。
- PDFエンジンを組み込む前に、モデルのAPIを固める

## 6. 検証方法

- Python版の既存テスト37件を継続実行
- C++モデルのページ順、回転値、削除後のインデックスをテスト
- PDFエンジン導入後は、同じ入力PDFに対するページ数・順序・回転・出力PDFを比較
- GUI導入後は、実機でD&D、保存、Undo、Markdown PDF出力を確認

### 6.1 現在の検証結果

- `cmake -G "MinGW Makefiles" -S core/native -B core/native/build` 成功
- `cmake --build core/native/build --config Release` 成功
- `QuickMarkPDF_cli.exe --help` 成功
- `QuickMarkPDF_cli.exe demo` 成功（追加・並べ替え・90度回転・削除を確認）
- `ctest --test-dir core/native/build --output-on-failure` 成功
- `cmake --build core/webview2/build --config Release` 成功
- `QuickMarkPDF_webview.exe` 起動確認成功
- Python版の既存テスト37件は全件PASS（Qt終了時のWindows固有終了コードはCIで許容済み）

## 7. リスク・懸念

- MuPDFのライセンス条件が配布方式と合わない可能性
- C++でのPDF編集・CJKフォント・暗号化PDF対応の実装量が大きい
- MermaidをWebView2に残すと完全な依存削減にはならない
- Python版とC++版の並行期間中に仕様差が発生するため、比較テストを先に作る
