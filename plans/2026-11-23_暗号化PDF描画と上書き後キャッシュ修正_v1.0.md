# 計画書: 暗号化 PDF の描画と上書き保存後のキャッシュ修正 (v1.0)

## 目的
脆弱性修正 (`plans/2026-11-23_脆弱性修正_結果_v1.0.md`) の作業中に見つけた、別の機能不具合 2 件を直す。
1. パスワード付き PDF は、パスワードで開いても描画とテキスト取得が失敗する。
2. 並べ替えて上書き保存すると、直後の 0 ページ目が古い内容のままになる。

## 現状分析 (旧・新ビルドの実バイナリで確認済み)
- 不具合 1: `main_gui.cpp` の `handle_render_page` / `handle_get_text_layout` (とテスト用 API の `get_text_layout`) は `PdfBackend::render_page` / `get_text_layout` をパスワードなしで呼ぶ。pdfium のキャッシュは「パス + パスワード」が一致したときだけ使うため、パスワードで開いた文書でも `password required` で失敗する。画像出力とテキスト抽出は `PdfManager` が `known_passwords_` を渡すので問題ない。
- 不具合 2: `PdfManager::overwrite_source` は一時ファイルへ保存してから元ファイルを置き換える。`PdfBackend::save` が無効化するキャッシュは一時ファイルのパスだけで、元ファイルのパスのキャッシュ (置き換え前の古い文書) が残る。そのため、置き換え後に `source_page` を振り直したページが、古い文書のページ順で描画される。実バイナリで、並べ替え後の 0 ページ目の本文が古いままになることを確認した。

## 変更内容
- `src/engine/pdf_backend.h/.cpp`: 指定パスのキャッシュだけを無効化する `PdfBackend::invalidate_document_cache(path)` を公開する (既存の内部関数を呼ぶだけ。パスワードも消去される)。
- `src/engine/engine.h/.cpp`:
  - `PdfManager::render_page(page_index, target_width)` と `PdfManager::get_text_layout(page_index)` を追加する。ページの元ファイルに対応する `known_passwords_` を渡して `PdfBackend` を呼ぶ。範囲外のインデックスは `std::out_of_range`。
  - `overwrite_source` の成功後に、元ファイルのキャッシュを無効化し、そのパスの `known_passwords_` を消去 (ゼロクリア) する。置き換えた後のファイルは暗号化されていないため。
- `src/app/main_gui.cpp`: `handle_render_page` と `handle_get_text_layout` と、テスト用 API の `get_text_layout` を、新しい `PdfManager` のメソッドに切り替える。
- `tests/engine_tests.cpp`: テストを追加する。
  - パスワードで開いた暗号化 PDF が、`render_page` と `get_text_layout` で失敗しない。
  - 並べ替えて上書き保存した直後の `get_text_layout(0)` が、並べ替え後の 0 ページ目の本文を返す。
  - 上書き後は、暗号化だった文書のパスワードが消去されている (パスワードなしで描画できる)。

変更しないもの: UI、保存・書き出しの流れ、V-3 の警告 (暗号化 PDF を上書きしようとしたときの警告と新規保存への切り替え)、`PdfBackend` の既存の公開 API の挙動。バージョン番号。Git 操作 (commit / push)。

## 検証方法
1. `python scripts/build.py test`: 追加テストを含め全件成功。
2. `obs.py` (今回の検証用スクリプト) を新しいテスト用ビルドで実行し、(a) 並べ替え → 上書き保存 → `get_text_layout(0)` が `PAGE-TWO` を返す、(b) 暗号化 PDF をパスワードで開いたあとの `get_text_layout` がエラーにならず本文を返す、ことを確認する。
3. `tests/e2e/security_regression.py` を再実行し、既存の全チェックが成功のままであること。
4. `python scripts/build.py all` で本番ビルドを作り、`dist` を更新する (起動中のインスタンスがあればビルドが失敗するので、その場合は終了をお願いします。こちらからは終了させません)。

自動化できない範囲 (結果文書に明記する): 画面でのサムネイル・プレビューの実際の見た目 (暗号化 PDF を開く、並べ替えて上書き保存する操作)。

## リスク
- 暗号化 PDF のテキスト取得・描画が初めて実際に動くため、pdfium が暗号化 PDF の一部で別のエラーを返す可能性。テストで使う AES-128 の PDF 以外の方式 (RC4、AES-256) は手元で試せていない。
- `overwrite_source` の後で `known_passwords_` を消すため、上書きした暗号化 PDF は以降パスワードを求められない (上書き後のファイルが暗号化されていないので正しい挙動)。
- 範囲は小さい。計画外の変更が必要になったら、いったん止めて計画書を改版する。
