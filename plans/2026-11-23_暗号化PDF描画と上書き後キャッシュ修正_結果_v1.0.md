# 結果: 暗号化 PDF の描画と上書き保存後のキャッシュ修正 (v1.0)

対応する計画書: `plans/2026-11-23_暗号化PDF描画と上書き後キャッシュ修正_v1.0.md` (承認済み)
実施日: 2026-11-23

## 結論
2 件とも直した。旧ビルドと新ビルドで同じ再現スクリプトを実行し、挙動が変わったことを実バイナリで確認した。commit / push はしていない。

## 実施内容
- `src/engine/pdf_backend.h/.cpp`: `PdfBackend::invalidate_document_cache(path)` を公開 (指定パスのキャッシュだけを破棄し、パスワードも消去)。
- `src/engine/engine.h/.cpp`:
  - `PdfManager::render_page(page_index, target_width)` と `PdfManager::get_text_layout(page_index)` を追加。ページの元ファイルに対応する、開いたときのパスワードを渡して `PdfBackend` を呼ぶ。範囲外のインデックスは `std::out_of_range`。
  - `overwrite_source` の成功後に、元ファイルのキャッシュを破棄し、そのパスのパスワード記録を消去 (ゼロクリア) する。置き換えたファイルは暗号化されていないため。
- `src/app/main_gui.cpp`: `handle_render_page`、`handle_get_text_layout`、テスト用 API の `get_text_layout` を新しいメソッドに切り替え。
- `tests/engine_tests.cpp`: テスト 2 件を追加し、既存の 1 件を拡張。2 ページの本文付き PDF を作る補助関数も追加。

## 検証結果
1. `python scripts/build.py test` と `python scripts/build.py all`: 全件成功。追加したテストの内容は次のとおり。
   - パスワードで開いた暗号化 PDF が `render_page` / `get_text_layout` で失敗しない。範囲外のインデックスは例外。
   - 並べ替えて上書き保存した直後の `get_text_layout(0)` が、並べ替え後の 0 ページ目の本文を返す。
   - 暗号化 PDF を上書き保存したあと、パスワードなしで描画できる (既存テストの拡張)。
2. 実バイナリ (テスト用ビルド、旧ビルドと同じ再現スクリプト):
   - 並べ替え → 上書き保存 → 0 ページ目の本文: 旧 `PAGE-ONE` (古いまま) → 新 `PAGE-TWO` (期待どおり)。
   - 暗号化 PDF をパスワードで開いたあとのテキスト取得: 旧 `password required` のエラー → 新 ページサイズと空のテキスト (本文のない PDF のため) が返る。
3. セキュリティ回帰テスト `tests/e2e/security_regression.py` を新ビルドで再実行: 全チェック成功 (前回と同じ結果)。
4. `dist` を新ビルドに更新。`dist/QuickMarkPDF.exe` にテスト用の文字列は無く、ASLR / DEP / HighEntropyVA は有効のまま。

## 未検証
- 画面上のサムネイル・プレビューの実際の見た目 (暗号化 PDF を開く、並べ替えて上書き保存する操作)。手動確認をお願いします。
- テストに使った暗号化 PDF は AES-128 のみ。RC4 と AES-256 の PDF は試していない。
- 暗号化 PDF のテキスト取得は、本文のある暗号化 PDF では未確認 (テスト用の PDF は本文が空)。

## 補足
- 上書き保存した暗号化 PDF は、以降パスワードを求められない (上書き後のファイルが暗号化されていないため。V-3 の警告のとおり)。
