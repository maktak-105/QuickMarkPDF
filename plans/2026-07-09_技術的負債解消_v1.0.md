# 計画書: 技術的負債解消（重複コード整理・ログ統一・HF編集バグ修正・非同期化・未保存確認）(v1.0)

## 目的

コード解析で発見した、`document/refactoring-plan.md`（過去のリファクタリング計画）のPhase1〜4が中途半端なまま残っている状態を解消し、あわせて次の5点を実装する。

1. `dialogs/*.py` とmain_window.py内の重複ダイアログ定義を統合
2. `print` を `logging` に統一
3. ヘッダー/フッター（HF）を再適用したときに古いテキストが重ね書きされるバグを修正し、「一度入れても編集し直せる」ようにする
4. `workers.py` の `Worker` クラスを実際に配線し、読み込み・保存・画像エクスポートをバックグラウンド実行にする
5. 未保存の変更がある状態でアプリを閉じようとしたら確認ダイアログを出す（dirty flag）

**HFのPDF上の見た目・仕様（挿入位置・フォント・配置・「削除は元PDFへの再読込」という破壊的設計）は一切変更しない。** 変更するのは「複数回適用すると文字が重なる」という不具合のみ。

## 変更内容

### 1. ダイアログ重複解消
- **変更**: `dialogs/export_dialog.py` を main_window.py 版（クロップ範囲対応あり）の内容で上書きし、こちらを正とする。`dialogs/header_footer_dialog.py` は内容が同一のためそのまま維持。
- **変更**: `main_window.py` からクラス定義（165-484行相当）を削除し、代わりに `from src.pdf_editor.ui.dialogs import HeaderFooterDialog, ExportDialog` を追加。
- **変更しない**: ダイアログの見た目・項目・挙動（`get_settings()` の戻り値の形も含め完全に同一）。

### 2. print → logging 統一
- **変更**: `pdf_manager.py` / `thumbnail_panel.py` の先頭に `import logging; logger = logging.getLogger(__name__)` を追加し、既存の `print(...)` を `logger.error(...)` または `logger.warning(...)` に置換（内容は今と同じメッセージ）。
- **変更**: `main.py` の `main()` 冒頭に `logging.basicConfig(level=logging.INFO)` を追加し、コンソールにログが出るようにする（現状は logger を呼んでもハンドラ未設定で info ログが出ない）。
- **変更しない**: ログの出力先（ファイル出力等は今回スコープ外、コンソールのみ）。

### 3. HF再適用時の重ね書き修正
- **変更**: `pdf_manager.py` に private helper `_reload_pages_from_disk()` を新設し、`remove_header_footer()` の「元ファイルから再読込 + 回転再適用」ロジックをそこに移す。
- **変更**: `add_header_footer()` の冒頭（ページ数チェックの直後）で `self._reload_pages_from_disk()` を呼んでから、新しい設定でテキストを挿入する。これにより「何度呼んでも常にクリーンな状態から1回だけ適用される」形になり、重ね書きが起きなくなる。
- **変更**: `remove_header_footer()` は `_reload_pages_from_disk()` を呼ぶだけに簡潔化（外部から見た挙動は変わらない）。
- **変更しない**: `add_header_footer` / `remove_header_footer` の公開シグネチャ、挿入されるテキストの内容・位置・フォント。`main_window.py` の `edit_header_footer` の呼び出しフローも変更不要（既に「設定変更→`add_header_footer`呼び出し」という形になっている）。
- **懸念**: 毎回全ドキュメントを閉じて再読込するため、ファイル数・ページ数が多い場合はHF適用がわずかに遅くなる可能性がある（下記リスク参照）。

### 4. workers.py の実配線
- **変更**: `main_window.py` に汎用ヘルパー `_run_in_background(func, on_success, on_error=None, busy_message="処理中...")` を追加。役割：
  - 多重実行防止（既に処理中なら何もしない）
  - ツールバーを一時的に無効化 + ステータスバーに `busy_message` 表示
  - `Worker(func)` を生成し `finished` / `error` シグナルを受けてUIを再有効化した上で `on_success` / `on_error` を呼ぶ
  - `Worker` / `QThread` インスタンスを `self._active_worker` 等に保持し、実行中にGCされないようにする
- **変更**: 以下をこのヘルパー経由に書き換え（既存の成功時・失敗時の処理内容はそのまま `on_success` / `on_error` に移植するのみ）：
  - `open_pdfs` → `self.pdf_manager.load_pdfs(paths)` をバックグラウンド化
  - `export_images` / `_on_image_extract_requested` → `self.pdf_manager.export_pages_to_images(...)` をバックグラウンド化
  - `save_pdf` / `_export_selected_as_pdf` → `self.pdf_manager.save_as(...)` / `save_selected_pages(...)` をバックグラウンド化
- **変更しない**: `add_header_footer`（HF適用）は元の計画書通り今回も同期のまま（対象外）。ダイアログの入力→設定確定までの同期フローも変更しない。
- **懸念**: PyMuPDFオブジェクトはスレッドセーフではないため、バックグラウンド処理中に別の操作が同時に `pdf_manager` を触らないよう、上記の多重実行防止で担保する。

### 5. dirty flag + closeEvent
- **変更**: `MainWindow.__init__` に `self._is_dirty = False` を追加。
- **変更**: 以下の成功時に `self._is_dirty = True` を設定：PDF読み込み成功、ページ並び替え、ページ回転、HF適用/削除、ファイルを閉じる。
- **変更**: `save_pdf` 成功時に `self._is_dirty = False`。
- **変更**: `closeEvent(self, event)` をオーバーライドし、`self._is_dirty` が True なら `QMessageBox.question` で確認、「いいえ」相当なら `event.ignore()`。
- **変更しない**: Markdownモードの保存フロー、ウィンドウタイトルの形式（"*"等のインジケータ追加はスコープ外）。

### 6. テスト
- **変更**: `tests/test_pdf_manager.py` に回帰テストを追加：`add_header_footer` を異なる設定で2回連続実行し、保存後のテキストに古い内容が残っていないこと・新しい内容のみ含まれることを検証。
- **変更しない**: 既存テストはすべてそのまま green を維持することを確認する。

## 検証方法

1. `python -m unittest discover tests` を実行し、既存テスト＋新規HF回帰テストが全てPASSすること。
2. `python main.py` を起動し、以下を手動確認：
   - 複数PDFを開く → 並び替え・回転 → ヘッダー/フッター適用 → 「名前を付けて保存」→ 生成PDFにヘッダー/フッターが正しく1つだけ入っている。
   - 同じPDFに対してヘッダー/フッター設定ダイアログを再度開いて内容を変更し「適用」→ 保存 → 古いテキストが残っておらず、新しい設定のみ反映されている（本修正の主目的）。
   - HF「削除」→保存→元の内容に戻る（回転は維持）。
   - 大きめのPDF（数十ページ）やページ数の多い複数ファイルを開く/保存/画像エクスポートする際、処理中もウィンドウが固まらず操作可能（プログレス表示は簡易でよい）。
   - 何らかの変更をした状態でウィンドウを閉じようとすると確認ダイアログが出る。「いいえ」でキャンセルされ、保存後は確認なしで閉じられる。
   - ダイアログ（ヘッダー/フッター設定・画像エクスポート設定、クロップ範囲含む）の見た目・項目が今までと変わっていない。
3. コンソール出力にログ（エラー時など）が表示されることを確認。

EXEビルド（PyInstaller）での最終確認は本プランでは必須としない。必要であれば実装完了後に別途依頼する。

## リスク

- ダイアログ統合時、`dialogs/export_dialog.py` を上書きする際に main_window.py 版との差分を見落とすと、クロップ機能などが欠落する可能性がある → 統合後に diff で完全一致を確認する。
- HF修正により `add_header_footer` が毎回全ドキュメントを再読込するようになるため、ファイル数・ページ数が多いケースでは体感速度がやや低下する可能性がある（今回は同期のまま。将来的に気になる場合は別途スレッド化を検討）。
- バックグラウンド実行化により、処理中に他の操作（別ファイルを開く、別の保存を始める等）が可能に見えてしまうと不整合を招くため、多重実行防止の実装漏れがないよう注意する。
- `closeEvent` の確認対象はPDF編集操作のみ。Markdownプレビュー→PDF変換の未保存状態は今回のdirty flag管理に含めない（既存動作のまま、明示的にスコープ外）。
