### V-1 Markdown XSS と防御層
- 新規 `src/ui/js/markdown.js`: `app.js` から Markdown 変換の純関数 (`escapeHtml`、`renderInline`、`markdownToHtml`、`protectMath` 等) を移す。DOM に依存しないので Node から読み込める。出力は benign な入力では現状と同一にする。
  - `escapeHtml` は `& < > " '` をエスケープする。
  - リンクの URL は `http:` / `https:` / `mailto:` / `#…` のみ許可し、それ以外 (`javascript:` 等、空白や制御文字で偽装したものを含む) はリンクにせずテキスト表示にする。
  - 画像の URL は `http:` / `https:` / `data:image/(png|jpeg|gif|webp);base64,` のみ許可する。相対パスの画像は読み込めないので alt テキスト表示にする (挙動変更)。
  - `renderInline` は「コード → 画像 → リンク → 強調」の順にプレースホルダ方式で処理する。属性値の中を後続の正規表現が書き換えないようにするため。
  - 数式 `$…$` / `$$…$$` は復元時に `escapeHtml` してから戻す。MathJax は DOM のテキストを読むので数式として動く。
- `app.js`: 上記関数を削除して `markdown.js` を使う。Mermaid は `securityLevel: 'strict'` にする。
- `scripts/bundle_html.py`: `markdown.js` を `app.js` の前にインラインする。CSP の `<meta>` を生成し、インライン script の SHA-256 をビルド時に自動計算して `script-src` に入れる。
  - CSP 案: `default-src 'none'; script-src 'self' <ハッシュ>; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`
  - `script-src` にハッシュを使うのでインラインのイベントハンドラ属性 (`onerror=` 等) も止まる。Mermaid / MathJax が eval を要求する場合は実測して計画を改版する (勝手に `'unsafe-eval'` を足さない)。
- `main_gui.cpp`:
  - `WebMessageReceived` で `get_Source()` が `kAppOrigin` で始まる場合のみ処理する。
  - `NavigationStarting` で `kAppOrigin` 以外への遷移を拒否する。
  - `NewWindowRequested` を `Handled=TRUE` にし、`http:` / `https:` のみ既定ブラウザで開く。
  - COM ハンドラのクラスを既存パターンどおり追加する。

### V-2 画像出力の出力先検証
- `engine.cpp` / `engine.h`: 出力ファイルの計画関数 (出力パスの一覧を返す) を追加し、`export_pages_to_images` から使う。
  - `prefix` は Windows のファイル名に使えない文字・区切り文字・制御文字・100文字超を拒否する。
  - 最終パスの親が `output_dir` と一致することも確認する (二重の防御)。
  - 不正時は全ページ分を `errors` に入れて書き込まない。
- `main_gui.cpp` の `handle_export_images`:
  - `output_dir` は絶対パスのみ許可する (`\\.\` は拒否)。
  - 承認済みフォルダ (フォルダ選択ダイアログ、`get_export_defaults` でネイティブが算出した既定、ユーザー確認済みのフォルダ) 以外、または既存ファイルを上書きする場合は、ネイティブの確認ダイアログを出す。テストモードでは自動承認する。
  - 確認したフォルダはそのセッション中は再確認しない。

### V-3 暗号化 PDF の保存
- `pdf_backend.cpp`: pdfium の `FPDF_GetSecurityHandlerRevision` を追加し、`PdfDocumentInfo` に `encrypted` を持たせる。
- `engine.cpp` / `engine.h`: `PdfManager::has_encrypted_sources()` を追加する (オーナーパスワードのみの PDF も検出できる)。
- `main_gui.cpp`:
  - 暗号化ソースを含むとき、上書き保存は選べず新規保存のみとし、「暗号化は保持されません」の警告ダイアログ (続行 / キャンセル) を出す。
  - PDF 切り出しにも同じ警告を出す。
  - 文言は `tr()` で日英対応にする。

### V-4 WebView2 の絞り込み
- 製品ビルドで次の 2 つを設定する (テスト用ビルドでは設定しない)。
  - `put_AreDevToolsEnabled(FALSE)`: F12、Ctrl+Shift+I、右クリックの「検証」による開発者ツールを封じる。
  - `put_AreBrowserAcceleratorKeysEnabled(FALSE)`: 再読み込み (F5 / Ctrl+R)、ページ内検索 (Ctrl+F)、印刷 (Ctrl+P) などブラウザ固有のキーを封じる。Ctrl+C / V / A / Z や矢印キー等の編集・移動系は止まらない。アプリ独自のショートカット (Ctrl+O、Ctrl+S、Ctrl+Z、Delete、矢印) は画面側のスクリプトが処理するので動く想定で、手動で確認する。
- 設定しない (ユーザー判断)。
  - `put_IsStatusBarEnabled`: リンクにマウスを乗せたときのリンク先 URL 表示を残す。
  - `put_AreDefaultContextMenusEnabled`: 標準の右クリックメニュー (「印刷」「コピー」等) を残す。
- 印刷の扱い: Ctrl+P は止まるが、標準メニューの「印刷」は使える。アプリ独自の印刷機能 (`window.print()` 等) は追加しない。Markdown の PDF 書き出しは専用の API (`PrintToPdf`) を使うため影響を受けない。
- 標準の右クリックメニューを残すため、メニュー内の「検証」は DevTools 無効化によって使えなくなる想定。

### S-1 リソース上限
- `render_page` の幅は 1〜4096 (JS の最大 4000 に合わせる)、総ピクセル数 64M 超は縮小する。
- 書き出し dpi は 1〜1200、総ピクセル数 150M 超のページはエラーにする (Letter 1200dpi は約 135M で通る)。
- `extract_int` はオーバーフローで飽和させる。

### S-2 テスト用 API の分離
- `QUICKMARKPDF_ENABLE_TEST_API` マクロで TCP API、`QUICKMARKPDF_TEST_OPEN_PATHS` フック、`is_test_mode()`、`QUICKMARKPDF_OFFSCREEN` を囲む。製品ビルドは既定で無効。
- `scripts/build.py` に `testapi` モードを追加し、`build/intermediate/QuickMarkPDF_testapi.exe` を作る。
- テスト用ビルドのみ: 受信バッファ上限 (1MB) と `SO_EXCLUSIVEADDRUSE`、実ハンドラを呼ぶ `ui_message` コマンド、WebView 内の検証用に `eval_js` / `get_eval_result` コマンド、WebView2 の設定値 (DevTools・ブラウザ固有キー・ステータスバー・標準右クリックメニュー) を読み出す `get_webview_settings` コマンドを追加する。

### S-3 DLL 検索
- `pdfium.dll` を exe と同じフォルダのフルパスで読み込む。
- `wWinMain` の先頭で `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_DEFAULT_DIRS)` を呼ぶ。

### S-4 上書き保存
- 一時ファイル名を一意にし、既存なら使わない。`MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` で置き換える。
- 失敗時に元ファイルを壊しうる `copy_file` フォールバックを廃止し、失敗時は一時ファイルを消して元ファイルを残す。

### S-5 パスワードの消去
- CredUI のバッファ、受け取ったパスワード文字列、`known_passwords_`、pdfium キャッシュのパスワードを `SecureZeroMemory` で消去する (破棄・退避時)。
- ベストエフォートで、`std::string` のコピーすべては追跡できない。この限界は結果文書に書く。

### S-6 データフォルダ
- `%LOCALAPPDATA%\QuickMarkPDF\WebView2` に移す。新フォルダが無く旧 `%TEMP%\QuickMarkPDF_WVData` がある場合は、設定 (localStorage のサムネ大きさ等) を引き継ぐため一度だけコピーする。
- `LOCALAPPDATA` が取れない場合は従来の場所に戻す。環境変数 `WEBVIEW2_USER_DATA_FOLDER` による上書きは維持する。

### B-1 依存バイナリの検証
- `scripts/fetch_pdfium.ps1` と `scripts/fetch_webview2_sdk.ps1` に SHA-256 の固定値と検証を追加する。取得 → 検証 → 成功時のみ `third_party` を置き換える順に変える。
- 固定値は初回取得で得る値 (初回信頼) で、出所の署名検証ではない。この限界は結果文書に書く。

## 検証方法
1. **レンダラー**: `node tests/markdown_render_test.js`
   - XSS 入力 (診断で使った 3 経路、`JaVaScRiPt:`、`java\tscript:`、`data:text/html`、`vbscript:`、エンティティ偽装、二重エスケープ) がすべて無害化されること。
   - 正常系の比較: `README*.md`、`docs/*.md`、`HISTORY*.md`、`plans/*.md` を旧実装 (git HEAD の `app.js` から抽出) と新実装で変換し、差分が意図した変更のみであること。差分は結果文書に列挙する。
2. **ブラウザ (内蔵ブラウザ)**: 再ビルドした埋め込み HTML で診断時の PoC を再実行し、スクリプトが動かないこと。通常の文書で Mermaid (フローチャート・シーケンス図)、MathJax (`$E=mc^2$` 等) が描画され、コンソールに CSP 違反が出ないこと。CSP 単体の確認として、描画経路を通さず `innerHTML` に `<img onerror>` を直接入れても止まること。
3. **エンジン**: `python scripts/build.py test` で新規テスト (prefix 拒否・パス計画・上限・暗号化検出・上書き保存の失敗時に元ファイルが残ること) を含め全件成功すること。
4. **製品ビルド**: `python scripts/build.py all` が成功し、`dist` を更新する (更新前の旧 exe を比較用に作業用フォルダへ退避)。PE ヘッダの ASLR / DEP / HighEntropyVA が有効のままであること。環境変数 `QUICKMARKPDF_TEST_PORT` を設定しても製品 exe がポートを開かないこと。
5. **テスト用ビルドでの再現テスト** (診断時の `e2e.py` を拡張):
   - V-2: `ui_message` 経由の `export_images` で、`../` と絶対パスの `prefix` が拒否され、出力先フォルダ外にファイルができないこと。
   - V-1 の端から端まで: 悪意ある `.md` を開いても PDF 読み込み後にファイルが書かれないこと。旧 exe では書かれることを対照として再確認する。
   - 本物の WebView2 上で `eval_js` により、CSP がインラインハンドラを止めること、`location.href` による外部遷移がブロックされること、`window.open` が既定ブラウザ経由になること。
   - S-3: 無害な検証用 DLL (ロード時にマーカーファイルを作る) を `pdfium.dll` の名前で作業フォルダに置き、旧 exe ではロードされ、新 exe ではロードされないこと。
   - S-6: 新データフォルダが作られ、旧フォルダから設定が引き継がれること。
   - V-4: `get_webview_settings` で、製品ビルドは DevTools とブラウザ固有キーが無効、ステータスバーと標準右クリックメニューが有効のまま。テスト用ビルドは 4 つとも既定のままであること。
6. **B 項目**: ワークフロー YAML の構文確認、固定した SHA が GitHub API で実在すること。取得スクリプトは、ハッシュを誤った値にした実行で `third_party` を壊さず中断すること。取得したアーカイブの `pdfium.dll` が手元の `third_party/pdfium/bin/pdfium.dll` と一致すること。
7. **ダウンロード (許可をお願いします)**: ハッシュ算出と照合のため、作業用フォルダ (リポジトリ外) へ次の 2 つを取得する。`third_party` には触れない。
   - `pdfium-win-x64.tgz` — `https://github.com/bblanchon/pdfium-binaries/releases/download/chromium%2F8009/pdfium-win-x64.tgz` (約 6MB 想定)
   - `Microsoft.Web.WebView2.1.0.2903.40.nupkg` — `https://www.nuget.org/api/v2/package/Microsoft.Web.WebView2/1.0.2903.40` (約 10MB 台の想定)

自動化できず、検証できない範囲 (結果文書に「未検証」と明記する):
- V-3 の警告ダイアログ (モーダルのため。述語のテストとコード確認まで)。
- S-5 のメモリ消去 (コード確認のみ)。
- CI 上の動作 (CodeQL の JavaScript 解析、SHA 固定後のワークフロー、来歴証明、choco 固定)。
- Windows の確認ダイアログの実画面 (手動確認をお願いする)。
- V-4 の実際の効き方 (設定値は自動で確認できるが、キー入力と標準メニューの表示は手動確認をお願いする): F12 / Ctrl+Shift+I で開発者ツールが開かないこと、F5 / Ctrl+P が効かないこと、アプリ独自のショートカット (Ctrl+O、Ctrl+S、Ctrl+Z、Delete、矢印) が動くこと、右クリックの標準メニューに「印刷」が出て使えること。

## リスク
- レンダラーの移動で正常な Markdown の見た目が変わる恐れ。新旧比較で差分を確認する。リンク・画像の許可リスト化により、相対パスの画像・ファイルリンク・`javascript:` 等は表示が変わる (意図した挙動変更)。
- CSP が Mermaid / MathJax を壊す恐れ。実測して、動かなければ計画を改版する。
- 画像出力で手入力したフォルダは、最初の 1 回だけ確認ダイアログが出る (使い勝手の変化)。
- 暗号化 PDF は上書き保存できなくなる (新規保存のみ)。
- V-4 により Ctrl+P (印刷)、F5 / Ctrl+R (再読み込み)、Ctrl+F (ページ内検索) が使えなくなる。印刷は右クリックの標準メニューで行う。標準メニューの「印刷」が実際に出るかは手動確認になる。出ない場合は計画書を改版して対応を決める。
- `SetDefaultDllDirectories` が一部のシェル拡張や共通ダイアログに影響する恐れ。通常の起動・ファイル選択・保存で確認する。
- 手元の `dist` を差し替える。旧 exe を退避してから行う。起動中の場合はビルドが失敗するので、その時は自分が起動した PID のみを終了する。
- ビルド堅牢化フラグ (stack protector 等) が CI の choco 版 MinGW でリンクできない恐れ。手元では確認できるが CI は未検証。
- 作業範囲が広い。段階ごとにビルドとテストを通す。計画外の変更が必要になったらいったん止めて計画書を改版する。
