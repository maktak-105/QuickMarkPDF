# Python版自動テスト整備 実施結果 v1.0

実施日: 2026-08-19
対応する計画書: `plans/2026-08-19_Python版自動テスト整備_v1.0.md`

## 1. 実施内容

計画書の6階層すべてを実装した。

1. **ダイアログガード**（`tests/conftest.py`）: `QFileDialog.*` / `QMessageBox.*` / `QInputDialog.getText` / `QDialog.exec` をオートユースフィクスチャで一括パッチ。未登録の呼び出しは `UnexpectedDialog` を即座に送出する。応答は `dialog_responses.push(name, value)`（1回消費）/ `.allow(name, value)`（無制限）で登録。実際の `QDialog` サブクラス（`ExportDialog`/`PreferencesDialog`/手組み`QMessageBox`）はコーラブル応答でインスタンスを設定してから閉じられる。ガード自体は `tests/test_dialog_guard.py`（9件）で検証済み。
2. **単体テスト**: 既存6本（37件）はコード変更なしでpytest経由に移行、全pass。
3. **結合テスト**（`tests/test_main_window_flows.py`、18件）: 実際の`MainWindow`を生成し、開く（CLI引数式／ダイアログ式）・パスワード保護PDF・回転・削除・元に戻す・ドラッグ並べ替え（実シグナル発火）・上書き保存・名前を付けて保存・保存キャンセル・PDF切り出し・画像エクスポート・環境設定・Markdownモード切替・未保存変更での終了確認（続行/キャンセル両方）を、すべて実際のディスク書き込みまで検証。
4. **見た目テスト**（`tests/visual/`、4件）: `QWidget.grab()` と `tests/visual_baselines/` の基準PNGをPillowで比較（平均ピクセル差許容値3.0/255）。初回実行で基準画像を作成、2回目以降で差分ゼロを確認。
5. **体感速度テスト**（`tests/perf/`、5件）: 50ページPDF読み込み・20ページ回転／並べ替え／元に戻す／画像エクスポートの所要時間を計測し、`tests/reports/perf.json` に記録（緩やかな閾値でハング・重大劣化のみ検知）。
6. **実画面テスト**（`tests/real_screen/`、2件、既定実行から除外）: `QUICKMARKPDF_REAL_SCREEN=1` を事前設定した上で実ウィンドウを表示し、`QTest.mouseClick`/実際のメソッド呼び出しで操作、スクリーンショットを `tests/reports/real_screen/` に保存。**実機で実行し、2件ともpass。** 実際の日本語UIが正しく表示され、クリックでページ選択が切り替わることを目視確認済み。
7. **実行手段**: `run_tests.py`（リポジトリ直下）が pytest を呼び出し、JUnit XML・カバレッジHTML・`tests/reports/summary.md`（pass率・失敗一覧・所要時間表）を生成する単一入口。

付随して以下も実施:

- `requirements-dev.txt`（pytest/pytest-qt/pytest-timeout/pytest-cov）、`pyproject.toml`（pytest設定）を新規作成し `.venv` にインストール・動作確認。
- `document/environment.md` / `_jp` を新規作成（README既存リンク先だったが未作成だった）。テスト階層・ダイアログガードの使い方・既知の制限をまとめた。
- `README.md` / `README_jp.md` の「C++バックエンドへ移行中」という記述を実状（Python版が仕様の正、C++移植は中止）に修正し、削除済みの `document/spec.md` 等・`plans/2026-08-18_C++移植_v1.0.md` への死リンクを解消、テスト節を追加。

## 2. 計画からの差分

- `main_window` フィクスチャで `QSettings` を一時INIファイルへリダイレクトする対応を追加した（計画時は想定していなかった）。`MainWindow.__init__` が `QSettings("maktak-105", "QuickMarkPDF")` で実レジストリ（`HKCU\Software\...`）を読み書きしており、`closeEvent` のテストがこれを汚染する可能性があったため。
- カバレッジ計測（`pytest-cov` を用いた `--cov=src`）を `run_tests.py` に追加した。計画書には明記していなかったが、依存関係に含めていた以上、レポートに繋げないと死重量になるため実施。現状カバレッジは70%（`main_window.py` 65%、`thumbnail_panel.py` 66%）。100%到達は今回のスコープ外とした。
- `PreferencesDialog`・Markdownモード切替のテストを追加した（計画書には明記していなかったが、低コストで実施できたため）。

## 3. 検証結果

- `PYTHONPATH` 不要（`pyproject.toml` の `pythonpath` 設定で自動解決）で `pytest` 実行、既定スイート **75/75 pass（100%）**。
- `run_tests.py` 実行で `tests/reports/summary.md`・`results.xml`・`htmlcov/`・`perf.json` が正しく生成されることを確認。
- ダイアログガードの効果を実地でも確認: 実画面テスト作成中に、未保存変更ありでの `window.close()` が実際に `QMessageBox.question` を呼び出そうとし、応答未登録のため**即座に例外で失敗**（ハングせず）することを実機で再現・確認した。これはまさに本整備が対象とする失敗モードの直接的な検証になっている。
- 実画面テスト（`QUICKMARKPDF_REAL_SCREEN=1 pytest -m real_screen tests/real_screen`）を実機で実行し2件ともpass。取得したスクリーンショット（`tests/reports/real_screen/after_click_page2.png`）で日本語UIの実際の表示とクリック操作の反映を目視確認済み。
- **既知の制限（重要）**: 開発環境のオフスクリーンQtプラットフォームには日本語フォントが無く、`tests/visual_baselines/` の基準画像は日本語テキストが豆腐（□）で描画される。構造的な回帰検知（レイアウト崩れ・要素欠落）には有効だが、実際の日本語表示の検証には実画面テストが必要（上記の通り実機確認済み）。
- 実画面テストの副産物として、実ウィンドウ表示時（QtWebEngine読み込みと重なるタイミング）に `Windows fatal exception: code 0x8001010d`（COM再入警告）がstderrに出力されることを確認したが、プロセスは落ちずテストはpassした。害のない既知の挙動としてテストファイルにコメントで記録した。
