# 計画書: 同梱・依存ライブラリの更新と鮮度チェックの仕組み (v1.0)

## 目的
`docs/investigations/2026-11-23-security-audit.md` の B-4 (同梱ライブラリが最新ではない) に対応する。
1. pdfium、WebView2 SDK、Mermaid を、上流で確認した新しい版へ更新する。MathJax は据え置く (理由は下記)。
2. 版が固定されたまま黙って古くなることを防ぐため、上流との差を確認するスクリプトと、週次の確認ワークフローを追加する。

## 変更内容
### pdfium → chromium/8165
- `scripts/fetch_pdfium.ps1` の既定の版とハッシュを更新する。ハッシュは GitHub のダイジェストと、取得したアーカイブの SHA-256 が一致することを確認してから固定する。
- スクリプトで `third_party/pdfium` を置き換え、再ビルドする (`dist/pdfium.dll` はビルドが `third_party` からコピーする)。
- `engine_tests` は pdfium の関数を全部読み込むため、新しい版でも関数が揃っていることがテストで分かる。

### WebView2 SDK → 1.0.4370.26
- `scripts/fetch_webview2_sdk.ps1` の既定の版とハッシュを更新する。ハッシュは取得した nupkg の SHA-256。NuGet のカタログが記録する SHA-512 とも照合する。取得した `WebView2Loader.dll` の Authenticode 署名が有効 (Microsoft) であることも確認する。
- 新しい `WebView2.h` を手元の MinGW でコンパイルできるかが最大の不確実点。通らない、またはテストが落ちる場合は 1.0.4314.35 を試し、それも駄目なら据え置いて理由を結果に記す。

### Mermaid → 11.17.2
- npm のパッケージ (`mermaid-11.17.2.tgz`) を取得し、レジストリが記録する SHA-512 と照合してから、`package/dist/mermaid.min.js` で `resources/vendor/mermaid/mermaid.min.js` を置き換える。ライセンスファイルに差があれば同じく更新する。
- 12.3.0 にしない理由: メジャー更新で図の見た目が変わる恐れがあり、サイズも約 2MB 増える。11.17.2 でも既知の勧告はすべて修正済み。12.3.0 にしたい場合は、承認時に指示してください (同じ手順で、描画確認を厚くします)。

### MathJax は 3.2.2 のまま
- 公開された勧告がなく、4.x はフォントの扱いが変わるため、完全にオフラインかつ CSP (`connect-src 'none'`) のもとで描画できるかの評価が要る。評価は別の計画にする。診断書に据え置きの理由として記録する。

### 鮮度チェックの仕組み (新規)
- `scripts/check_dependency_updates.py`: pdfium (GitHub Releases)、WebView2 SDK (NuGet)、Mermaid・MathJax (npm) の最新版と、リポジトリが使っている版を表で比べる。使っている版は、2 つの `.ps1` の既定値と `resources/vendor/` のファイルから読み取る。遅れがあれば終了コード 1。MathJax は「意図的に据え置き」として、遅れでも失敗にしない (理由を表示)。`--verify-vendor` で、`resources/vendor/SHA256SUMS` の記録と実ファイルのハッシュを照合する。
- `resources/vendor/SHA256SUMS` (新規): 同梱している 2 つのファイルのハッシュ。
- `.github/workflows/dependency-freshness.yml` (新規): 週 1 回と手動で上記スクリプトを実行する。遅れがあるとジョブが失敗し、GitHub から通知が出る。Actions はコミット SHA で固定する。
- `docs/environment.md` と `docs/environment_jp.md` に、更新手順と確認方法を追記する。

### 変更しないもの
UI、機能、バージョン番号 (4.2.0)、`HISTORY.md`、Git 操作 (commit / push)。MathJax。WebView2 Runtime。

## 検証方法
1. `python scripts/build.py all`: ビルドとエンジンテストが全件成功すること (新しい pdfium で全関数が読み込め、描画サイズなどが変わらないこと)。
2. `python scripts/build.py testapi` のあと、`python tests/e2e/security_regression.py` を新しいテスト用ビルドで実行し、全チェックが成功すること。`node tests/markdown_render_test.js` も成功すること。
3. ブラウザ検証: 新しい Mermaid を入れた UI で、フローチャート・シーケンス図・クラス図・状態遷移図・ガント図・円グラフ・XY チャート・アーキテクチャ図・レーダー図の例が描画され、CSP 違反が出ないこと。`strict` で `javascript:` リンクが動かないこと。旧版との見た目の差を目視で比べる。
4. 成果物: `dist/pdfium.dll` が取得したアーカイブ内のものと一致すること。`WebView2Loader.dll` の署名が有効であること。ASLR / DEP / HighEntropyVA が有効のままであること。`dist/QuickMarkPDF.exe` にテスト用コードが無いこと。
5. 鮮度チェック: `python scripts/check_dependency_updates.py` を実行し、更新後は MathJax 以外が最新と表示されること。ハッシュを書き換えた状態では `--verify-vendor` が失敗すること。
6. 取得スクリプトは、ハッシュを誤った値にした実行で `third_party` を壊さず中断すること (前回と同様)。

自動化できず検証できない範囲 (結果文書に明記する): 画面での PDF のサムネイル・プレビューの見た目 (新しい pdfium での描画の差)、週次ワークフローの実際の動作 (次の実行で初めて確認できる)、古い WebView2 Runtime との組み合わせ (この PC は 157 のみ)。

## リスク
- 新しい pdfium の描画や文字抽出の結果が変わる、または関数の署名が変わってビルドできない恐れ。テストで検出できる範囲は限られる。
- 新しい `WebView2.h` が MinGW でコンパイルできない恐れ (上記のとおり代替手順あり)。
- Mermaid 11.17.2 で、既存の文書の図の見た目や挙動が変わる恐れ。CSP と `strict` のもとでも描画できるかを確認する。
- 本番ビルドで `dist` を置き換えるため、起動中のインスタンスがあれば失敗する。その場合は終了をお願いします (こちらからは終了させません)。
- 週次ワークフローは CI 上でしか動かせない。スクリプト本体は手元で動作確認する。
- 計画外の変更が必要になったら、いったん止めて計画書を改版する。
